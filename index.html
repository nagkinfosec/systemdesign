System Architecture Mental Model

Think in architecture concepts first: where traffic enters, how it is protected, how it is routed, how compute scales, where state lives, and how slow work is decoupled from the user request.

Synchronous request path State and consistency path Decoupled async path
Step 01 Clarify the product problem Start with users, core use cases, traffic shape, read/write ratio, data sensitivity, and business criticality.
Step 02 Prioritize non-functional goals Choose the order of importance: latency, availability, consistency, scalability, security, cost, and operability.
Step 03 Draw boundaries and ownership Separate edge, trust boundary, API contracts, domain services, data ownership, async workflows, and operations.

State, consistency, and integration layer
Hot State / Cache Optimizes repeated reads and session-like lookups, but needs invalidation, TTL, and fallback strategy.
Source of Truth Primary databases protect correctness, transactions, constraints, and durable writes.
Integration and Large Objects Queues decouple workflows; blob storage handles files, exports, media, and large payloads.
Architecture flow patterns
Query / Read path

Optimize for latency: edge cache first, then service cache, then read replica or search index. Reads can tolerate controlled staleness when the product allows it.

Command / Write path

Optimize for correctness: validate, authorize, commit to the source of truth, publish a change event, and invalidate or refresh derived views.

Async workflow path

Optimize for resilience: queues absorb spikes, workers retry safely, idempotency prevents duplicates, and dead-letter queues preserve failed work.

Core system design concepts to reason about
Scale Horizontal growth Add stateless instances behind load balancers; shard or partition state only when needed.
Reliability Failure isolation Use timeouts, retries with backoff, circuit breakers, bulkheads, and graceful degradation.
Consistency Freshness tradeoff Choose strong consistency for money, identity, and inventory; eventual consistency for feeds and analytics.
Observability Trace every request Correlate logs, metrics, and traces across gateway, services, queues, and databases.
